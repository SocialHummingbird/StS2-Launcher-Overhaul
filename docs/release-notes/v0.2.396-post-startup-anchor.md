# v0.2.396-post-startup-anchor

Published: 2026-07-07

## Scope

`v0.2.396-post-startup-anchor` is a diagnostic and hardening APK for GitHub issue #34. It targets the remaining crash profile where the game reaches `NMainMenu` and then returns to launcher/home before the first post-startup heartbeat.

## Changes

- Android successful-startup path keeps `GameStartupWrapper` anchored after startup observation instead of completing immediately.
- Normal Android startup avoids creating launcher startup recovery/status overlay nodes for successful game starts.
- Existing post-startup trace, heartbeat, and native lifecycle diagnostics remain available.
- The release keeps the local tester package identity used by the current public APK line: `com.sts2launcher.overhaul.fork.local`.

## Local Validation

- Device: Samsung `SM-F966B`, ARM64.
- Public Start Game reached real `NMainMenu`.
- Post-startup probes logged alive at 1s, 3s, 10s, and 30s.
- Heartbeats logged alive at 60s and 120s, with the persisted marker later reaching 180s.
- Focused logs showed no `NativeFallback`, `FATAL EXCEPTION`, AndroidRuntime fatal, `SIGSEGV`, `SIGABRT`, fatal signal, ANR, LMKD kill, app `has died`, or Godot static-string cleanup markers.
- Steam Cloud Push was not run.

## Known Limitation

This release does not fix the Pixel / PowerVR / Android 17 issue #34 repro. The reporter's `log6.txt` proves `v0.2.396` reaches `NMainMenu`, logs `NGame.GameStartup completed`, passes the main-menu guard, hides launcher recovery UI, and activates the Android post-startup task anchor. About 200ms later Godot emits static-string cleanup errors and the app restarts into launcher/bootstrap.

The remaining failure no longer looks like launcher handoff, shader warmup, recovery UI, or dev-console handling. It is currently treated as a broader Android GPU/resource compatibility issue on the PowerVR/OpenGL ES fallback path, where Godot is forced to decompress or convert unsupported texture formats such as `RGBFloat`, `BPTC_RGBA`, and `DXT1`/`DXT5` during main-menu/deferred asset loading.

Next work should focus on Android-safe startup asset loading and texture/import compatibility rather than another narrow lifecycle patch.
