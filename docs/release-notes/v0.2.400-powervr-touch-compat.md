# v0.2.400-powervr-touch-compat

Release: https://github.com/SocialHummingbird/StS2-Launcher-Overhaul/releases/tag/v0.2.400-powervr-touch-compat

## What changed

This release targets the remaining PowerVR touch failure reported in GitHub issue #34.

- Records the live Godot graphics adapter, vendor, driver, and rendering method in `graphics_device.txt`.
- Detects PowerVR, ImgTec, and Imagination GPUs and routes every launcher renderer choice through OpenGL Compatibility, the path on which the reporter's device accepted touch.
- Enforces the same decision at the native Android restart boundary so a saved Auto, Vulkan, or Safe Start preference cannot bypass the compatibility route.
- Keeps the visible renderer controls aligned with the effective PowerVR policy and preserves the requested/effective modes in diagnostics.
- Leaves non-PowerVR renderer selection unchanged.
- Retains the v0.2.399 PowerVR shader-cache workaround, public runtime activation fix, and per-mod activation evidence.

No Slay the Spire 2 game files were modified. The change is confined to launcher renderer selection, Android startup routing, diagnostics, tests, and documentation.

## Connected-device validation

The exact APK above is installed on Samsung SM-F966B, Android 16 / API 36, ARM64, Qualcomm Adreno 830. Pulling the installed `base.apk` produced the same SHA-256 as the release artifact.

- Auto remained Vulkan, reached the real `NMainMenu`, and accepted touch.
- Explicit Vulkan remained Vulkan.
- Safe Start remained unforced Auto/Vulkan and reached `NMainMenu`.
- Explicit OpenGL reached `NMainMenu` and accepted touch.
- A synthetic PowerVR graphics marker changed a saved Vulkan request to effective OpenGL, reached `NMainMenu`, wrote the three-second post-startup probe, and accepted touch.
- BaseLib and Quick Restart loaded in modded public startup; Quick Restart installed its three exact Harmony targets and the game reached `NMainMenu` with `Running Modded - Loaded 2 mods`.
- The focused process trace contained no `MethodAccessException`, Android fatal, native signal, or ANR.
- Renderer policy tests, the 12-check PowerVR compatibility audit, the mod evidence reviewer, APK structure/ABI checks, crypto-patch checks, and update-compatibility checks passed.
- Steam Cloud Push was not performed.

## Issue #34 status

This APK implements the compatibility route indicated by the reporter's v0.2.399 tests: Vulkan reached the game but lost touch, while OpenGL accepted touch. The policy handoff is validated locally, but the connected device uses Adreno rather than PowerVR. Reporter testing on the Pixel 10 Pro / PowerVR D-Series DXT-48-1536 is still required before issue #34 can be closed.

## Important limitations

- You must own Slay the Spire 2 on Steam. The APK does not contain the game or bypass Steam ownership checks.
- This requires an ARM64 Android device and remains community tester software rather than a supported Android port.
- PowerVR is intentionally restricted to OpenGL Compatibility. The reporter observed a slow first menu while graphics were compiled, followed by normal gameplay and later menu use.
- BaseLib uses a reduced Android-safe initialization path; broad mod compatibility is not implied.
- SavesMerger uses launcher save-path compatibility patches rather than loading its upstream DLL/PCK directly.
- Steam Cloud Push was not tested. Back up saves and Pull from Steam Cloud before considering any Push operation.
