# StS2 Launcher v0.2.416

This release follows the `v0.2.412` startup/cloud hardening build with three fixes found during ARM64 hardware validation.

## What Changed

- Android now selects the expected `sts2.dll` identity from the active runtime source. A patched runtime-pack assembly is validated against `compatibility.json` / `patch_validation.json`; ordinary dependencies remain validated against the selected Steam game installation.
- Assembly-cache updates remain transactional. Staging is fully validated before promotion, and an interrupted, stale, corrupt, or mismatched runtime pack cannot replace an existing valid active cache.
- **Restart launcher** on the native diagnostics screen clears pending normal/Safe Start preferences and carried launch payloads before routing once to `LauncherActivity`, preventing immediate fallback loops.
- A launcher IME policy now suppresses Android/Samsung keyboard requests caused by Godot's hidden focused editor during launcher startup, boot cleanup, and non-editor resume/focus paths.
- Deliberately focused launcher text fields still request the keyboard normally.
- Downloaded game content, shader warmup, the silent boot-sound stub, and Steam Cloud overwrite safeguards are unchanged.

- The exact non-debuggable APK was installed as an in-place update on ARM64 Samsung `SM-F966B` / Android 16.
- Its pulled installed `base.apk` SHA-256 exactly matches the release artifact.
- Cold start completed the readiness-driven four-second Godot-to-StS2 Launcher sequence and exposed the rendered launcher with `mInputShown=false`.
- Public Start Game validated patched runtime-pack `sts2.dll` size `9305600` and SHA-256 `5c3c2bead75b05883073e7ed99420c1241ecd0f99c0407bda8677a9ec7caca27`, promoted the staged cache, reached real `NMainMenu`, and logged 1s, 3s, 10s, 30s, and 60s heartbeats.
- A cumulative debuggable build exercised a controlled missing-validation-report failure. Startup retried once, preserved the valid patched cache, routed to `NativeFallbackActivity` without constructing `GodotApp`, and returned through the actual **Restart launcher** button after clearing the pending game payload.
- Android assembly, lifecycle, startup-routing, native-recovery, IME, and boot-transition regressions pass.
- Managed Release compilation, Gradle release assembly, ARM64 APK structure/crypto verification, update compatibility from `v0.2.412`, and the non-mutating cloud production-path probe pass.

## Validation Limits

- Issue #36 still needs confirmation on the reporter's Xiaomi tablet. Samsung evidence cannot prove Xiaomi lifecycle, storage, or firmware behaviour.
- Issue #35 still needs confirmation on the reporter's Odin device. No real Steam Cloud Push was performed; the Push production-path test used only an in-memory fake store.
- The forced-failure probe used a debuggable validation APK built from the same cumulative source because app-private runtime evidence is intentionally inaccessible in the final non-debuggable APK.
- Automated lock/sleep/power-key testing was excluded. No hardware lock state was changed during this release validation.
- Modded startup, every Steam branch, every GPU/driver, split-screen, accessibility services, and broad device compatibility are not claimed by this focused smoke test.
- This remains unofficial tester software on the local test signing channel. You must own Slay the Spire 2 on Steam; the launcher contains no game files.
