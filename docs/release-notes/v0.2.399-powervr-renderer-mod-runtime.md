# v0.2.399-powervr-renderer-mod-runtime

Release: https://github.com/SocialHummingbird/StS2-Launcher-Overhaul/releases/tag/v0.2.399-powervr-renderer-mod-runtime

## What changed

This release targets the leading cause of GitHub issue #34 and hardens public-branch mod loading.

- Backports Godot 4.5.2's transform-feedback shader-cache workaround for every PowerVR renderer while retaining the project's custom Godot 4.5.1 base.
- Replaces the broken forced-OpenGL path with explicit Auto, Vulkan, OpenGL, and Safe Start renderer policies.
- Records the selected/effective renderer, Android lifecycle events, historical process-exit reasons, post-startup probes, and heartbeat evidence in support diagnostics.
- Routes Android launch-readiness SHA-256 work through the Java crypto bridge, fixing a native signal 11 crash found while enumerating selected mods.
- Restarts into the prepared public runtime when the active game assembly differs from the selected runtime.
- Records per-mod payload, runtime-load, Harmony-target, partial-compatibility, substitute, failure, and verification evidence.
- Correctly correlates nested runtime manifest paths with their selected Workshop roots.

Validated on Samsung SM-F966B, Android 16 / API 36, ARM64, Qualcomm Adreno 830:

- Public/default Auto selected Vulkan Forward Mobile and reached the real `NMainMenu`.
- Explicit OpenGL selected Godot Compatibility / GLES 3.2 and reached the real `NMainMenu`.
- Post-startup probes appeared at 1, 3, 10, and 30 seconds, followed by 60- and 120-second main-menu heartbeats.
- The focused package logs contained no `NativeFallback`, fatal Android exception, `SIGSEGV`, `SIGABRT`, signal 11/6, app ANR, or target-process low-memory kill.
- The public runtime pack was generated, selected, validated, and activated with matching prepared/active Android assembly hashes.
- BaseLib loaded without errors in partial Android compatibility mode.
- Quick Restart loaded without errors with three Harmony targets. Its in-game `Restart Room` action was exercised in an active Ironclad combat and successfully restored the room while the app remained alive.
- SavesMerger used the launcher's Android save-path compatibility substitute as designed.
- The public mod activation marker recorded three enabled mods and zero failed runtime loads.
- The repository Workshop evidence reviewer passed all 76 checks.
- Steam Cloud Push was not performed.

## Issue #34 status

This release contains the leading PowerVR fix, but issue #34 is not yet confirmed resolved. The connected validation device uses an Adreno 830 GPU, not PowerVR. Reporter `Sparrow115`, or another tester with a PowerVR device, must test this exact APK before the issue can be closed.

The original failure is consistent with the Godot OpenGL transform-feedback shader-cache problem tracked in [Godot issue #113911](https://github.com/godotengine/godot/issues/113911) and addressed for all PowerVR renderers by [Godot PR #111329](https://github.com/godotengine/godot/pull/111329).

## Important limitations

- You must own Slay the Spire 2 on Steam. The APK does not contain the game or bypass Steam ownership checks.
- This requires an ARM64 Android device and remains community tester software rather than a supported Android port.
- PowerVR hardware validation is still outstanding.
- BaseLib uses a reduced Android-safe initialization path; broad mod compatibility is not implied.
- SavesMerger's upstream DLL/PCK is substituted by launcher save-path patches and was not loaded directly.
- Steam Cloud Push was not tested. Back up saves and Pull from Steam Cloud before considering any Push operation.
