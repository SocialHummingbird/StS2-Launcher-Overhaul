# v0.2.435-preload-repair-local-r2 — Android preload and Mono startup repairs

This ARM64 release repairs two existing implementations involved in Android startup. It is published as the latest release at the user's request with full phone acceptance still incomplete. Resolution of the intermittent title-screen freeze is not yet established.

## Changes

- The existing preload patch now finds both publicized Android members and private desktop members. All six field and three method shape checks, eight outstanding loads, four finalizations per frame, fallback limits, cache accounting, failure handling and VFX ordering remain intact.
- The existing native Mono bootstrap enters GC-safe native execution after first delegate creation. The original state reproduces a worker GC wait; the repaired transition allows collection while the native host waits and preserves later delegate creation and callbacks.
- The older PR's two test scaffolds are consolidated into the existing preload test file. No new production loader, watchdog, state owner, preference or persisted format is introduced. The Android startup-task lifetime anchor is retained.

## Validation

156 managed tests, 56 Android/JVM tests and 12 deterministic save-safety scenarios pass. The existing real-resource probe preserves ownership, cache, fallback/failure, ordering and completion behavior. The actual staged Android Mono regression reproduces the original wait and completes 64 collections with callbacks preserved after the transition. The APK passes ARM64 contents, Android crypto and update-identity checks.

On the Samsung SM-F971B / Android 17, this exact APK completed two full cold Modded and two Vanilla launches: Common preload, at least 60 seconds of responsive title interaction, Settings, gameplay entry and Save and Quit. The original BaseLib, Import Vanilla Saves and Quick Restart selection remained active. Saves and credential loading remained available after the in-place update.

A third Modded launch completed Common but was interrupted when the user removed the phone; it is excluded. No r2 freeze was observed during these tests. Three comparison pairs and 18 Modded acceptance launches remain: eight cold, six warm, two background/resume and two lock/unlock. Real Android Steam transfers and broader device/mod compatibility remain unverified. The [evidence report](https://github.com/SocialHummingbird/StS2-Launcher-Overhaul/blob/v0.2.435-preload-repair-local-r2/docs/title-screen-preload-repair-2026-10-02.md) retains the failed first candidate and distinguishes local checks from device results.
