# v0.2.439 - Mod update controls and correct launcher update checks

Workshop update controls now appear before the installed-mod list. Launcher update
prompts use Android build numbers, so a newer locally labelled build is not offered
an older stable APK. This release also includes the bounded save-upload batch work.

## Changes

- Keep **Update Workshop mods** visible before a growing mod list. Regression
  checks cover four/six installed mods, pointer clicks, and phone/tablet layouts.
- Compare the release APK's `versionCode` with the installed build before offering
  an update. Verify the matching `.apk.json` asset's size, GitHub SHA-256 digest,
  APK identity and package. Equal/older builds do not prompt; genuinely newer
  builds remain eligible. Downloaded APKs retain package, certificate, architecture,
  minimum Android version and actual build-number checks.
- Upload changed saves through three bounded file workers. After a positive
  commit acknowledgement, matching Steam SHA-1 and explicit uncompressed size
  verify the upload; missing/unusable metadata uses one read-back download.
  Contradictory metadata fails verification. Deletions follow successful batch
  verification, and failure/cancellation drains workers before disposal.
- Add validation-only Cloud cleanup, preservation and stopped-frame crypto probes.
  These helpers and diagnostic timers are absent from the normal APK.

Game chunk-download behaviour is unchanged from v0.2.438. No percentage speed
improvement or completed live upload acceptance is claimed.

## Verification and remaining issues

- **283 managed tests**, **62 Android/JVM tests**, and **15 deterministic save-safety
  scenarios** passed. The managed suite passed again after merging into `main`.
- Desktop Godot UI interaction checks passed at phone/desktop sizes and Fold-sized
  tablet scales. These verify visibility and click routing, not a live Workshop update.
- Scoped C# formatting, validation-source generator guards and diff checks passed.
  Android lint retains **15 existing errors and 39 warnings, with zero new
  diagnostics**. This is not a clean lint result.
- Release selection was checked against the published v0.2.438 metadata: equal/newer
  installed builds were skipped and an older build was offered the update.
- The previous Fold campaign preserved all 617 original Cloud files and removed its
  nine owned test paths. Normal candidate `438025` passed offline startup and a
  1,178-entry local comparison with zero semantic user-data differences.
- Full live Cloud upload acceptance remains incomplete. An empty-file PUT returned
  HTTP 403; its cause remains unresolved because a later read-only preservation
  download timed out before the isolated repeat could upload anything.
- The Android crypto bridge can time out while Godot's frame thread is stopped;
  an unhandled timer callback can terminate the app, including on resume after OS
  process freezing. The shared failure mechanism was reproduced with an offline
  Fold fixture. It is **not fixed** in this release.
- Production Cloud delete verification still expects an explicit tombstone; Steam
  can instead return `FileNotFound` after an acknowledged deletion, causing failure
  reporting even though the file was removed. Test-only cleanup handles its owned
  files separately; production deletion policy is unchanged.

The final release APK was not installed on the Fold. Its automatic-update dialog,
full download/permission/install cycle, live Workshop replacement and the remaining
Cloud scenarios still need device acceptance. Detailed observations are in the
[validation record](https://github.com/SocialHummingbird/StS2-Launcher-Overhaul/blob/main/tools/DownloadValidation/README.md#follow-up-empty-cloud-put-and-stopped-frame-crypto-timeout).
