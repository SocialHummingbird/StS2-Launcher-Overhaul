# StS2 Launcher v0.2.425

**UNVERIFIED MOD-LOADING CANDIDATE — ONE-DEVICE ACCEPTANCE INCOMPLETE**

This is an experimental ARM64 prerelease, not a stable, phone-ready, or
release-ready build.

## What changed

- Workshop and manual mods now converge through one validated launch plan and
  loader path.
- Missing or corrupt mod selection defaults to Vanilla; Modded requires an
  explicit selection.
- The launcher distinguishes installed, enabled, loaded last launch, partial,
  failed, stale, and not-tested mod states.
- Home shows the selected mode, enabled-mod count, and next save namespace.
- The representative importer receives its compiled Godot script registration
  before its PCK scenes resolve.
- Runtime results fail closed instead of treating absent evidence as a loaded
  mod.
- The Android-safe BaseLib path omits the demonstrated hanging CustomPile
  compatibility patch while retaining the confirmed BadgePool activation
  target. BaseLib is still reported as `Partial`.
- Current and legacy `ModManager.Initialize` shapes are handled through the same
  loader integration.

## Validation

The exact attached APK passed:

- .NET Release build with zero warnings and zero errors.
- Focused local-save, synchronization, and mod probe: 9/9.
- Launcher navigation and mod-journey interaction test.
- Fresh-process desktop fixture checks for Vanilla, disabled, and active modes.
- Exact desktop BaseLib plus ImportVanillaSaves chain.
- APK content, Android crypto-patch, package, signer, version, update-continuity,
  and ARM64-only ABI inspection.

A limited run on one ARM64 Android device showed both selected mods discovered,
payload-loaded, initialized, and activated; a real `modded/` save path was used
and the game reached the main menu. The user observed marked improvement and
mods appearing to work.

That run did not capture the importer's unmistakable control or a matching
launcher result after relaunch. A later freeze/crash was reported after the
retained filtered log ended; the retained log contains no fatal signal for that
later report. The device is no longer connected. The exact one-device journey
therefore remains incomplete.
