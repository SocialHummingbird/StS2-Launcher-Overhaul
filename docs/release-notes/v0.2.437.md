# v0.2.437 - Restore game-owned input initialization

The game now initializes its own keyboard and controller bindings. The launcher
loads real settings first when needed and keeps the Android Steam-to-Godot
controller fallback. This removes the copied mapping initializer that left
keyboard bindings empty on the tested split-map public beta.

## Changes

- Restore the selected game's defaults, saved-binding restoration and
  version-specific input layouts through its original `NInputManager.Init`.
- Preserve loaded settings. If settings loading fails, return a faulted task to
  the game's existing error handling.
- Remove the redundant mapping builders, detached settings fallback, unused
  reflection helpers and premature success message: 131 production lines removed,
  13 added. No replacement mapping subsystem or PR #49 test scaffolding is added.

## Recorded verification

The merged source passed 220 managed regression tests. The release build with
analyzers and scoped managed formatting check passed; 56 Android/JVM tests passed.
Android lint still reports the same 15 errors and 39 warnings as the retained
pre-merge baseline, with no new diagnostic identities. The existing Gradle
configuration does not fail on lint errors.

Phone testing used candidate **0.2.437-input-init-local / 437001** on a Samsung
SM-F971B running Android 17, with public-beta game v0.111.0. The original v0.2.436
APK reproduced empty keyboard columns and an ineffective E end-turn key after a
cold start. With the candidate, default E end turn worked in both input modes
after resetting through the game UI and restarting. Saved Q end turn in
Mouse + Keyboard and R end turn in Keyboard-Only also worked after another cold
restart; the former E key no longer ended the turn in either mode. Each tested
press advanced one turn. Startup, the Godot controller fallback and touch input
were observed working without input-initialization exceptions.

These checks used ADB application-level key events. Actual confirm-shortcut
activation and physical keyboard/controller input were not verified. Tests used
an initially empty profile, then restored the original bindings, mode and profile
and removed only that temporary profile. A Steam save conflict was left unresolved
without selecting either copy; acceptance ran offline.

The final APK, **437002**, was built from commit
`9066e566dca7b131cfc9cddbeada4a97f935e607`. It passed contents, Android crypto,
signing and update compatibility checks against v0.2.436 and candidate 437001.
This final APK has not been installed on a phone. The separate long-run stability
procedure remains incomplete.

See the [current testing record](https://github.com/SocialHummingbird/StS2-Launcher-Overhaul/blob/main/docs/current-android-status.md)
for exact game identity, individual observations and remaining checks.
