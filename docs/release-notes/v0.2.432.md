# v0.2.432 — Startup responsiveness and faster preparation

This ARM64 release reduces blocking startup work and title-screen resource-loading bursts associated with freezes and Android “Wait or close” dialogs.

## Changes

- Android prepares game files on a serial worker instead of blocking the activity thread. Lifecycle-safe completion avoids duplicate launch routing and stale activity callbacks.
- A launch-local, file-validated snapshot avoids repeated archive hashing during activity startup. Managed identity checks can reuse a valid existing digest cache without writing during read-only checks.
- Preload Steam Cloud synchronization starts on a worker so synchronous connection setup does not block Godot's UI thread.
- Android asset preloading limits outstanding resources to eight and finalizes at most four per pass, with cooperative time budgets. Cached resources, VFX ordering, and completion handling are preserved.

These changes address identified blocking paths; they do not establish that every intermittent title-screen freeze is resolved. A single native resource operation cannot be preempted by the cooperative budget.

Install using Android's Update action or `adb install -r` over the matching application. No uninstall or data reset is required. The APK includes no Steam game files. Checksum and build metadata are attached.

## Validation

- 140 managed tests, 53 Android unit tests, and 12 deterministic save-safety scenarios passed.
- The actual game AssetLoadingSession loaded 161 synthetic resources in the desktop Godot probe. The original implementation exceeded the backlog bound; the patched implementation stayed within eight outstanding resources and four finalizations per pass. Cached repetition completed in three frames.
- API 36 x86_64 emulator checks on the same source's local universal candidate passed four Android worker/lifecycle instrumentation scenarios and native fallback cold-launch, input, and resume checks. These checks do not execute the Android game title screen: the existing x86 Godot/Mono crash guard selects native fallback.
- The published ARM64 APK passed release build, contents/ABI, Android crypto, and update-identity verification. No physical device was available; this exact ARM64 artifact and full Android gameplay were not device-tested. Save probes use deterministic fixtures, not live Steam Cloud.
