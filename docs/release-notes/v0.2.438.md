# v0.2.438 - Chunk downloads and persistent resume

Game downloads and updates now assemble verified replacement files from existing
content and newly fetched Steam chunks. Pause and restart recovery retain verified
staging rather than restarting unfinished files.

## Changes

- Reuse matching chunks from current partial files, the selected installation,
  superseded partial downloads and other completed installed versions. Moved and
  repeated content is identified by depot, SHA-1 and uncompressed length.
- Fetch missing chunks through one bounded pool: three workers on Android and
  eight on desktop. One large file can use the whole pool.
- Keep pending manifests separate from completed install evidence. Resume verifies
  actual ranges; complete replacement files pass Steam hashes before promotion.
- Add Pause/Resume controls and resume routing before destructive redownload.
  Progress separates reused/resumed logical bytes from completed compressed payload.
- Retain unchanged Android-prepared PCKs only with authoritative ready evidence;
  reconstruct changed Steam content before Android preparation.
- Fix NUL-terminated manifest names across target, staging and donor paths. Apply
  normalisation before `.downloading` suffixes while retaining containment and
  duplicate-target checks.
- Remove obsolete files at the verified commit boundary so an old file cannot
  block a new implicit directory. Failed verification preserves the old files;
  deletion-only updates also complete cleanup.

Save synchronization, Workshop transfer behaviour and Android networking/crypto
were not redesigned. No permanent chunk cache or percentage speed claim is added.

## Verification and limits

- 266 managed regression tests and 56 Android/JVM tests passed. Scoped managed
  formatting passed. Android lint reports the existing 15 errors and 39 warnings;
  all 15 error source locations are unchanged from v0.2.437. It is not a clean lint pass.
- Fold candidate `438013` transferred and verified 3,160,619,181 logical bytes from
  the live beta manifest. Raw Steam PCK verification passed before preparation v2.
- Actual Pause, Resume, force-stop and relaunch retained verified staging. None of
  212 pause-verified or 387 restart-verified identities was fetched again; one PCK
  reached three logical workers.
- The real-CDN synthetic moved-range fixture reused 14,215,464 logical bytes,
  fetched exactly one missing 281,184-byte compressed chunk and matched the target
  SHA-1. Synthetic layout evidence is separate from a real release update.
- Full sandbox runtime readiness remains blocked: Java's native cache API reads
  the normal app directory while managed validation uses the sandbox. The identity
  guard rejected that mismatch before native cache preparation. It was not bypassed,
  and this is not an established production runtime failure.
- Normal candidate `438014` passed offline startup and a 1,178-entry preservation
  comparison with zero semantic user-data differences. Saves, credentials, installed
  versions and user settings were preserved; only expected runtime metadata differed.

The final release APK is rebuilt from committed source. Its packaging/signing and
source details are recorded before publication; no phone installation or fresh-game
gameplay result is claimed for that final artifact. Separate PCK corruption/retention,
real same-branch updates and paired performance comparisons remain unverified.
See the [full validation record](../../tools/DownloadValidation/README.md#manifest-filename-fix-and-focused-fold-verification-13-november-2026).
