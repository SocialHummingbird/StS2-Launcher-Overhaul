# v0.2.397-atlas-memory-compat

Published: 2026-07-11

## Scope

`v0.2.397-atlas-memory-compat` targets the remaining GitHub issue #34 crash profile on Pixel 10 Pro / Android 17 / PowerVR. Reporter `log6.txt` showed the game reaching real `NMainMenu`, then tearing down immediately after Android eagerly loaded every desktop-compressed texture atlas.

## What Changed

- Android skips the deferred `AtlasManager.LoadAllAtlases()` call instead of loading every non-essential atlas during startup.
- Card, relic, power, and potion atlas resource requests use individual texture files while the source atlas remains unloaded.
- Entries without an individual fallback remain eligible for lazy source-atlas loading, avoiding missing resources while keeping startup bounded.
- Desktop/non-Android atlas behavior is unchanged.
- Exact-runtime validation now checks the reporter assembly/PCK, fallback coverage, texture import formats, and all three Harmony patch targets.

## Why

The PowerVR/OpenGL ES path does not support several PC-oriented BPTC/DXT texture formats used by the Steam payload. Godot therefore decompresses and uploads those sheets as RGBA8. The three card atlas pages alone expand to about 166 MiB, with relic, power, and other sheets adding more pressure in the same short startup window. In `log6.txt`, static-string teardown starts about 200 ms after that eager atlas pass completes.

This release removes that eager burst and resolves atlas-backed resources incrementally. It does not modify or redistribute Slay the Spire 2 game files.

## Known Limitation

The reporter's Pixel 10 Pro / Android 17 / PowerVR device has not tested this release. The change directly targets the atlas-loading pattern immediately preceding their teardown, but this is not a confirmed PowerVR fix or broad device-compatibility signoff until that path is retested.

Please report the exact APK filename, device model, Android version, selected Steam branch, and a focused log if the app still returns home or restarts.
