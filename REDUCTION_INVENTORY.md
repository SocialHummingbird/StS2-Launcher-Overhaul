## Authority and disposition

Retain keeps the existing owner. Repair changes its implementation. Replace routes every caller to an existing owner and deletes the superseded implementation. Remove deletes unreachable code or production no-ops. File consolidation does not change responsibility.

## Apparent duplicates retained

An exact-body scan reviewed 1,383 managed method bodies of at least 40 tokens. Bootstrap branch hashing had an existing equivalent API and was replaced. Remaining groups:

- Workshop directory moves have equivalent low-level behavior, but sharing them would expose staging internals outside the allowed internal-interface scope. Promotion/rollback owners and unique logging/error paths remain local.
- Workshop path checks protect different download/staging mutation roots; each boundary still validates its own root. No generic path-policy owner is introduced.
- Workshop Log methods deliver different instance events. An event adapter would not remove a competing decision owner.

Managed/native authorization, discovery/validated readiness, startup lifetime, scene provenance, credential platform implementations and save/transfer separation remain intentional compatibility paths. Unproven candidates stay with these recorded reasons.

## Consolidation and evidence

`consolidation-provenance.json` maps 301 original source paths to 63 surviving responsibility files. All 1,468 member token sequences were verified unchanged before fragment deletion. Initialized fields construct independent values/collections rather than reading mutable sibling initializers. Existing classes/algorithms/platform boundaries remain. Pre-consolidation source and compiled public-surface comparison are retained.

The [cleanup report](docs/system-cleanup-2026-10-02.md) records final checks, APK checksum, review and limitations. Phone stability, the original freeze, Android mod/gameplay behavior and live Android Steam transfers remain pending under the existing [20-launch acceptance procedure](docs/launch-flow-audit-2026-10-02.md#physical-device-acceptance--pending-at-the-users-direction).
